# Ready-to-paste Manus build prompt

Build an **editable, frontend-only personal music player** named **Rosewood Listening Room**. Its purpose is to play MP3 files that I upload during a browser session or direct MP3 URLs that I am authorized to use. Do not bundle, scrape, fetch, or publish copyrighted music. Add a concise notice that users must upload or link only audio they own or are authorized to play.

Use React, TypeScript, and Tailwind/CSS. Make it responsive and accessible. The player must include an MP3 upload control (accepting multiple `.mp3` files), a form for adding an HTTPS or HTTP direct MP3 link plus optional song title and artist, a clear empty state, a selectable queue, previous/play-pause/next buttons, a seek bar, elapsed/total time, volume control, and a remove-track action. The audio element should run entirely in the client browser. Uploaded tracks should be session-only and not uploaded to a server. Direct links may fail where the source blocks browser playback; show a respectful inline playback error rather than attempting to bypass it.

Use the **Rosewood Listening Room** visual direction. The palette is dusty rose, bone paper, rosewood brown, oxblood, charcoal, and small antique-gold accents. The layout should be a left collection rail and a large right listening stage—not a centered dashboard. Use DM Serif Display for display titles, Manrope for UI text, and DM Mono for metadata. Add a charcoal vinyl disc with visible concentric grooves, a dusty-rose label, and a tonearm. The disc must rotate only while audio is actively playing and must pause immediately when audio pauses; respect `prefers-reduced-motion`. Avoid generic card grids, neon effects, purple gradients, or overly rounded components.

Create the logo as a text-free rose-petal spindle symbol. Use the branded hero art and two sleeve artworks as visual decoration, but never present them as songs, artists, ratings, reviews, or user content. Keep all music metadata based on the user's inputs. Put short comments at the beginning of the main page and global CSS explaining the design philosophy so future edits preserve the direction.

Before delivery, verify that uploads can be queued, a valid direct link can be added, controls work with the audio element, the selected queue item is visually clear, keyboard controls have labels/focus styling, and the page works at mobile width. Keep all edits in obvious locations: `client/src/pages/Home.tsx` for player behavior, `client/src/index.css` for styling and tokens, and `ideas.md` for the design spec.

> Suggested first edit after generation: replace the site name, then add an MP3 you are authorized to use from the **Add a track** panel. You can also change the dusty-rose token in `client/src/index.css` (`--rosewood-blush`) to make the theme your own.
